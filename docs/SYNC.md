# Анонимная синхронизация: инструкция владельца

Профиль — случайная фраза из 25 символов (~125 бит), рождается на устройстве. Никаких регистраций, e-mail, имён и паролей.
Из фразы (HKDF-SHA256) выводятся два независимых значения: **идентификатор записи** (необратимо) и **ключ AES-256-GCM**.
На сервер уходят только `id` и непрозрачный шифртекст — у вас как у владельца сервера нет ни читаемого прогресса, ни личных данных.
Один Worker обслуживает оба приложения (Glossa и Srpski): пространство имён — префикс id (`glossa.` / `srpski.`).

Пока `endpoint` пуст, облачная часть скрыта; работают офлайн-способы (файл экспорта/импорта и «код переноса»).

## Развёртывание Worker (один раз, ~5 минут)

Нужен бесплатный аккаунт Cloudflare и Node.js 20+.

```bash
cd sync-worker
npx wrangler login                        # откроется браузер, войдите в аккаунт Cloudflare
npx wrangler kv namespace create BLOBS    # выведет id namespace
```

1. Вставьте выданный `id` в `sync-worker/wrangler.toml` вместо `REPLACE_WITH_KV_NAMESPACE_ID`.
2. (Необязательно) задайте `ALLOWED_ORIGINS = "https://ваш-сайт.example"` — тогда Worker отвечает только вашему сайту.
   Пусто = любой источник: данные всё равно зашифрованы, а доступ — только по секретному id.
3. Деплой:

```bash
npx wrangler deploy
```

В выводе будет адрес вида `https://glossa-sync.<аккаунт>.workers.dev`.
Если `wrangler` ругается на блок `[[unsafe.bindings]]` (лимит запросов), закомментируйте его — Worker работает и без лимита.

## Подключить приложение

1. В `data/sync.js` впишите адрес **без** слэша на конце: `endpoint: 'https://glossa-sync.<аккаунт>.workers.dev'`
   (допустим только `https://`; для отладки — `http://localhost:…`). В Glossa `app: 'glossa'`, в Srpski `app: 'srpski'` — менять не нужно.
2. `node tools/build-sw.mjs` (обновит версию кэша), затем `npm test` и `node tools/validate.mjs`.
3. Опубликуйте приложение как обычно (push на хостинг / `npm run build:www` для Capacitor).
   Пользователи получат баннер «Доступна новая версия» → «Обновить».

## Проверка

```bash
curl https://glossa-sync.<аккаунт>.workers.dev/v1/health          # {"ok":true}
curl -i https://glossa-sync.<аккаунт>.workers.dev/v1/blob/glossa.00000000000000000000000000000000   # 404
```

Дальше в приложении: **Профиль → Профиль и синхронизация → Создать профиль** → статус «Синхронизировано».
В панели Cloudflare (Workers KV → BLOBS) появится одна запись с ключом `glossa.<32 hex>` — это нечитаемый шифртекст.

## Быстрый сценарий для себя

1. На первом устройстве: **Создать профиль**, записать фразу (менеджер паролей или бумага).
2. На каждом новом устройстве один раз: **У меня уже есть профиль** → ввести фразу (или открыть ссылку/QR из «Показать фразу»).
3. Всё. Синхронизация идёт сама: при запуске, через ~15 секунд после изменений, при возвращении сети и по кнопке.
   Прогресс сливается без потерь: на новом устройстве ваши локальные занятия не затираются.

## Как это защищено

- Фраза и никнейм лежат только в `localStorage` устройства (`glossa:sync:v1`) и не попадают в экспорт прогресса.
- Запись защищена ETag: `PUT` требует `If-Match` (обновление) или `If-None-Match: *` (создание). При конфликте клиент скачивает,
  сливает и повторяет.
- Ограничения Worker: размер ≤ 512 КБ, формат id `(glossa|srpski).<32 hex>`, формат блоба (версия 1), никаких логов, заголовки
  безопасности (`nosniff`, `no-store`, `no-referrer`, CSP `default-src 'none'`), CORS.
- Запись живёт 400 дней с последней записи; клиент подновляет её не реже раза в 30 дней.
- Ссылка/QR содержат фразу после `#` — браузер не отправляет её на сервер, а приложение стирает её из адресной строки.
- Честно: хостинг теоретически видит IP-адрес и время запроса (как при любом сайте). Потерянную фразу восстановить нельзя.

## Ограничения бесплатного тарифа Cloudflare KV

- ~1000 записей в день и ~100 000 чтений в день на аккаунт. Клиент пишет только при изменениях (с задержкой ~15 с),
  поэтому для личного/семейного использования этого достаточно.
- KV «в конечном счёте согласован» (до ~60 с между регионами): при одновременной записи с двух устройств в одну минуту возможна
  устаревшая проверка ETag; данные при этом не теряются — слияние выполняется на клиенте, и следующая синхронизация всё сглаживает.

## Слияние: правила

| Данные | Правило |
|---|---|
| Уроки | max мастерства, пика и лучшей точности; «пройден» = ИЛИ; история — объединение |
| SRS-карточки | побеждает карточка с более свежей отметкой `last` |
| Банк ошибок | по ключу побеждает более свежая запись (≤ 300) |
| XP по дням, счётчики | max |
| Серия | максимум по (последний день, длина); рекорд = max; паузы — объединение |
| Достижения | объединение, время — самое раннее |
| Настройки | последнее изменение (`settingsAt`) побеждает; вибрация и озвучка остаются на устройстве |

Известные ограничения: суммарные счётчики (`xpTotal`, число ответов) берутся по max, а не складываются, чтобы слияние было
идемпотентным; ошибка, исправленная на одном устройстве, может вернуться в банк с другого.

## Офлайн-способы без сервера

- **Экспорт/импорт** файла JSON — «Профиль → Настройки → Резервная копия» (импорт заменяет прогресс).
- **Код переноса** — «Профиль и синхронизация → Скопировать код» на одном устройстве, «Объединить с кодом» на другом
  (сжатие через `CompressionStream`, если есть; данные объединяются, а не заменяются).

## Удаление данных

Пользователь: «Удалить данные на сервере» (запрос `DELETE`) — запись удаляется, устройство выходит из профиля.
Владелец: удалить ключ в панели KV либо удалить весь namespace.
